# 01 · 整体架构

## 为什么不做纯网页

MiMo 开放平台（`api.xiaomimimo.com`）**不返回任何 CORS 头**：

```
OPTIONS /v1/platform/balance  → 404（没有预检响应）
GET     /v1/platform/balance  → 401（鉴权错误，且无 Access-Control-Allow-Origin）
```

浏览器里 `fetch` 直连必然被同源策略拦截，页面上只能看到 `Failed to fetch`。
因此两条可行路线：

1. **安卓端**：WebView 加载本地页面，请求交给原生 `HttpURLConnection` 发出，结果用字符串回传宿主页面 —— 没有浏览器 CORS 的概念。
2. **桌面端**：页面由本地 Node 服务提供，页面请求打到 `127.0.0.1` 的同源接口，再由 Node 用 `https` 模块转发。

两条路线都**不引入第三方代理**（用户明确否决 Cloudflare Worker / 自建中转）。

## 安卓端分层

```
┌──────────────────────────────────────────────┐
│ assets/index.html   单文件页面（UI + 业务）    │
│   ├─ 状态 state：账号、余额、用量、账单、配置   │
│   ├─ 渲染：Canvas 图表 + DOM 卡片              │
│   └─ 请求：window.MimoNative.get(url, key)     │
└───────────────▲──────────────────────────────┘
                │ @JavascriptInterface（同步返回 JSON 字符串）
┌───────────────┴──────────────────────────────┐
│ MainActivity（WebView 壳 + Bridge）            │
│   Net.java         HttpURLConnection GET       │
│   Alert/Receiver   AlarmManager + 通知         │
│   WidgetProvider   RemoteViews + Canvas 位图   │
└──────────────────────────────────────────────┘
```

### 原生桥协议

页面只依赖一个全局对象，其余全部是可选能力：

| 方法 | 作用 | 返回 |
|---|---|---|
| `get(url, key)` | 以 `Authorization: Bearer` + `api-key` 双头发起 GET | `{"status":200,"body":"..."}` |
| `clipboard()` | 读系统剪贴板（解决 Key 粘贴失效） | 文本 |
| `insets()` | 状态栏/导航栏 inset（物理像素） | `"top,right,bottom,left"` |
| `metrics()` | 布局诊断：density / 屏高 / WebView 高 | 字符串 |
| `setConfig(key, threshold, alertOn, hours)` | 写入后台预警配置 | void |
| `setBottomPad(dp)` | 底部留白档位（0 自动 / 具体 dp） | void |
| `requestNotifyPermission()` | Android 13+ 通知权限 | void |
| `checkNow()` | 立即跑一次后台检查 | void |
| `widgetStatus()` / `pinWidget()` | 小组件自检 / 一键添加到桌面 | 状态串 / void |

请求失败统一封装成 `{"status":0|4xx|5xx,"body":...}`，页面侧用 `parseMsg()` 把 401/429 翻译成人话。

### 数据流（一次刷新）

```
点击刷新 → 组装任务清单 → Promise.allSettled
            ├─ 余额（必选）
            ├─ 日用量（仅 MiMo）
            └─ 日账单（仅当停在"日账单" Tab）
        → 聚合 aggUsage() → 渲染余额卡/概览/趋势/模型/明细/账单
```

设计要点：

- **部分失败不毁数据**：任一接口失败只记录错误，保留上一次的成功数据并展示污染提示，避免"刷新一下全空"。
- **按需请求**：账单接口只在切到对应 Tab 才拉，减少调用次数（也减少被限流的概率）。
- **限流退避**：命中 429 时进入 45 秒冷却，期间仍然展示旧数据并倒计时自动重试；手动刷新最短间隔 20 秒。

## 桌面端分层

```
浏览器  http://127.0.0.1:8787
   └─ public/index.html（与安卓同源页面，fetchUrl 改为 /api/fetch）
        └─ Node server.js
             ├─ 静态托管 public/
             ├─ /api/fetch?url=&key=   → https 转发（仅 GET）
             ├─ /api/meta
             └─ ?mock=1                 → 本地生成演示数据
```

同一份页面通过 `typeof window.MimoNative === "undefined"` 判断运行环境，决定请求走原生桥还是本地接口，其余逻辑（聚合、图表、快照推算、多供应商）完全复用，只做布局与入口的适配。
