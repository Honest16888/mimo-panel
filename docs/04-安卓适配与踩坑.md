# 04 · 安卓适配与踩坑

设备基准：小米 17 Pro，Android 16 / HyperOS，屏幕 1220×2656，density 3.25。

## 1. API Key 粘贴不了

**现象**：设置里的 Key 输入框长按不弹系统"粘贴"菜单，只能一个字符一个字符敲。

**原因**：为了做自定义长按交互，代码里对输入框调了 `setLongClickable(false)` 并在
`OnLongClickListener` 里返回 `true` 消费掉事件——系统的文本选择/粘贴菜单正依赖这条通路。

**修复**：

1. 移除长按拦截，恢复 `setLongClickable(true)`
2. 更关键的是加了原生「粘贴」按钮：`Bridge.clipboard()` 直接读剪贴板文本，一步填满
   （不依赖系统菜单，也不受输入法影响，任何 ROM 都能用）

## 2. 顶部被状态栏压住

`setDecorFitsSystemWindows(false)` + 页面用 `--sat` 补齐的方案在部分 ROM 上会给到错误的 inset，
表现为内容钻到状态栏下面。

**最终方案**：回归标准窗口（内容区不延伸到状态栏），把 `statusBarColor` / `navigationBarColor` /
Decor 背景统一成 `#0b0d10`，让状态栏和页面同色，视觉上"连成一片"但不重叠。
insets 仍然通过 `Bridge.insets()` 上报，页面只在 top > 0 时写 `--sat` 作为兜底。

## 3. 底部黑边（耗时最久的问题）

**现象**：页面底部出现一条纯黑横带，图表被截断，看起来像 WebView 没铺满。

**排查过程与结论**：

| 版本 | 尝试 | 结果 |
|---|---|---|
| v1.4 | 原生给 WebView 加 padding | 黑带还在 |
| v1.5 | 识别限流保留旧数据 | 与本问题无关 |
| v1.6 | 去掉页面 `--sab` 避免双算 | 略好，仍有 |
| v1.7 | 加「底部留白」可调 + 布局诊断 | 拿到关键数据 |
| v1.8 | 强制 `LAYOUT_HIDE_NAVIGATION` 全屏 | 页面铺满了，但**切后台多任务卡片窗口比内容大、底部露白**，被用户当场指出 |
| v1.9 | 回归标准窗口 + 系统栏同色 | 达标 |

关键证据来自布局诊断：

```
insetTop=150, insetBottom=0, density=3.25, screenH=2269, webH=2419, padBottom=26
```

- `insetBottom = 0` → 黑带**不是导航条 inset 造成**，加 padding 只会让它更宽
- `webH(2419) > screenH(2269)` → WebView 的实际高度比屏幕还高，说明内容是被"垫高后截断"，
  而不是没铺到边

所以正解不是加 padding，而是**不要和系统抢窗口**：标准窗口下系统自己会给导航条留位，
我们只负责把那块区域涂成和页面一样的颜色。此后不再出现黑带，后台卡片也恢复正常比例。

## 4. 刷新过快被限流

**现象**：连续点刷新后返回 `Rate limit exceeded`，余额卡变空。

**修复三层**：

1. 手动刷新最短间隔 20 秒（`MIN_GAP`），期间按钮转圈但不发请求
2. 429 识别：进入 45 秒冷却，**保留旧数据不清空**，横幅倒计时结束后自动重试
3. 缩小请求面：日账单接口只在切到"日账单"Tab 时请求；自动刷新下限抬到 60 秒

## 5. 后台预警与开机自启

- `AlarmManager.setInexactRepeating` 按整点间隔跑一次检查（省电，不追求秒级精确）
- 命中余额阈值发通知，`NotificationChannel` id `mimo_alert`
- `BroadcastReceiver` 接 `BOOT_COMPLETED` 重新排闹钟（否则重启后预警静默）
- Android 13+ 需要 `POST_NOTIFICATIONS` 运行时权限，设置里给了一个"授权"按钮

## 6. 后台只认 MiMo

后台预警与小组件的数据来自原生 `Net.java`，它只实现了 MiMo 的余额与近 14 天消费。
多账号引入后，页面在切到非 MiMo 账号时**不写入 Key**（`setConfig("")`），
避免小组件显示上一个账号的残留数字。
