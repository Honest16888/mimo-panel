# 05 · 构建、签名与发布

## 为什么不用 Gradle

构建环境没有完整 Android Studio / Gradle 插件链，而 APK 的产物结构是确定的：
资源 + `classes.dex` + `AndroidManifest.xml` + `META-INF` 签名。
用 build-tools 里的五个工具按顺序拼一遍，就能稳定产出可安装 APK，而且构建时间只有几秒。

## 流水线

```
res/  ──aapt2 compile──►  res.zip
                            │
AndroidManifest.xml ──aapt2 link──►  unsigned.apk + gen/R.java
                            │
src/*.java + gen/R.java ──ecj──►  classes/*.class
                            │
                        d8 ──►  classes.dex
                            │
unsigned.apk + assets/index.html + classes.dex ──zip──►  合并
                            │
                     zipalign -p 4
                            │
                     apksigner（v1 + v2）
                            │
                       MiMoPanel.apk
```

对应 `android/build.sh`，需要的参数：

| 变量 | 说明 |
|---|---|
| `ANDROID_JAR` | `android-33/android.jar` |
| `BUILD_TOOLS` | 含 `aapt2 / d8 / zipalign / apksigner` 的目录 |
| `ECJ_JAR` | Eclipse 编译器（比 javac 少依赖，直接吃 android.jar 当 bootclasspath） |
| `KEYSTORE / KS_PASS / KEY_PASS` | 签名用，**不入库** |

要点：

- `aapt2 link` 第一次要带 `--java gen` 生成 `R.java`，否则 Java 编译找不到资源 id
- `assets/` 与 `classes.dex` 是在 `aapt2 link` 之后用 `zip` **追加**进去的（`aapt2` 不打包 dex）
- `zipalign -p 4` 必须在签名**之前**
- `apksigner` 同时开 v1/v2：老 ROM 认 v1，新系统认 v2

## 签名与升级

- **必须一直用同一个 keystore**。换签名 = 换应用身份，只能卸载重装（会丢本地配置和历史）
- `PKCS12` 格式，`--ks-pass` / `--key-pass` 分开传
- 每次改动都要抬 `versionCode`（当前 18 / `2.7`），否则系统拒绝覆盖安装

## 发布

- 仓库只放**源码与构建脚本**，不放 keystore、已签名 APK、真实 Key
- 桌面版直接 `node server.js`，无需打包；如果要分发给别人，压缩整个 `desktop/` 目录即可
- 网页版（可选）走豆包 HTML 发布链路：单文件 `index.html` 即可，注意浏览器端有 CORS 限制，
  真实数据仍需原生/本地服务
